# 04 首次启动与验证

## 1. 启动命令

### 1.1 推荐命令（实测）

```bash
cd /Users/changzechuan/TradeCryptoCoinProjects/gocryptotrader
./gocryptotrader -portfoliomanager=false
```

**为什么要加 `-portfoliomanager=false`**：portfolio manager 是**现货/余额导向**的（`engine/portfolio_manager.go`），它每分钟调一次 `UpdateAccountBalances` 并尝试给每种币找价格提供方。纯合约部署下 `portfolioAddresses.providers` 是关的，于是每分钟刷两条：

```text
[ERROR] | PORTFOLIO | Portfolio manager: UpdatePortfolio error: provider not enabled: CryptoID for currency BTC
```

实测：加这个 flag 后 ERROR 从 30 条降到 1 条（只剩"未配通知通道"），且**它不在 `dryRunParamInteraction` 列表里，不会触发 dry-run**（`engine/engine.go:927-937`）。

配置里只留了币安一个交易所，所以不需要 `-exchanges binance`（那个 flag 反而会强制 dry-run）。`connectionMonitor` 的默认探测目标（google/cloudflare/facebook）在网络畅通的机器上没问题；国内直连环境才需要 `-connectivitymonitor=false`，见 [01-环境准备](01-环境准备.md) §4.3。

**实测启动表现**（macOS arm64 / Go 1.27.0）：约 8 秒到全部子系统就绪，RSS 约 94 MB，`autoPairUpdates` 拉到 789 个 USDT-M 合约，SyncManager 首轮同步 10 个条目耗时 5.4 秒。

### 1.2 前台 vs 后台

前台（开发期推荐，Ctrl+C 退出）：

```bash
./gocryptotrader -connectivitymonitor=false
```

后台 + 日志重定向：

```bash
nohup ./gocryptotrader -connectivitymonitor=false > /tmp/gct.out 2>&1 &
echo $! > /tmp/gct.pid
tail -f /tmp/gct.out
```

停止：

```bash
kill -INT "$(cat /tmp/gct.pid)"     # 优雅退出，走 Engine.Stop
```

程序用 `signaler.WaitForInterrupt()` 监听 SIGINT/SIGTERM（`main.go:155` 阻塞在 `<-settings.Shutdown`），收到信号后调 `engine.Bot.Stop()`。

**注意**：`encryptConfig: 0` 或 `ntpclient.enabled: 0` 时后台运行会卡在交互式提问上。配置模板已经把这两个分别设成 `-1` 和 `-1`。

### 1.3 调试模式

```bash
./gocryptotrader -verbose -exchangeverbose -connectivitymonitor=false
```

- `-verbose`：提高引擎日志级别
- `-exchangeverbose`：打印每一次 HTTP 请求和响应体（等价于配置里 `exchanges[].verbose: true`，但会**强制 dry-run**）

排查币安接口问题时非常有用，能看到完整的 URL、签名参数、返回的 JSON 和错误码。

### 2.1 必须确认**没有**出现的告警

| 日志内容 | 含义 | 处理 |
| --- | --- | --- |
| `exchange Binance authenticated API support disabled due to default/empty APIKey/Secret/ClientID values` | Key/Secret 是占位符或空 | 填真实凭据，见 03 文档 §4.3 |
| `database support is disabled` / `database.ErrDatabaseSupportDisabled` | 数据库没开 | 要落历史数据就把 `database.enabled` 设 `true` |
| `config.json file not found in ...` | 配置文件找不到 | 复制到 `~/.gocryptotrader/config.json` |
| `Config is overwriting default endpoint URL values` | 你改了 `urlEndpoints` | 切测试网时是正常的，主网时说明配错了 |
| `gRPC proxy cannot be enabled when gRPC is disabled` | 网关开了但 gRPC 关了 | 两个一起开或一起关 |
| `order manager ... errInvalidFuturesTrackingSeekDuration` | `futuresTrackingSeekDuration <= 0` | 设成正数（纳秒） |

### 2.2 币安特有的正常日志

```text
[INFO]  | EXCHANGE | Binance: Fetching USDT margined futures exchange info
```

## 4. 验证券安永续链路

按顺序跑这四步，每步都通过说明对应链路是好的。

### 4.1 公共行情（不需要 API Key）

```bash
gctcli getticker --exchange Binance --pair BTC-USDT --asset usdtmarginedfutures
```

期望返回 `last_price`、`high`、`low`、`bid`、`ask`、`volume`、`mark_price`、`index_price` 等字段。

`ticker.Price` 的完整字段（`exchanges/ticker/ticker_types.go:28-57`）：`Last, LastSize, VolumeWeightedAveragePrice, High, Low, Bid, BidSize, Ask, AskSize, BaseVolume, QuoteVolume, Open, Open24Hour, PercentChange24Hour, Close, OpenInterest, OpenInterestValue, MarkPrice, IndexPrice, Pair, ExchangeName, AssetType, LastUpdated` 等。

如果报交易对未启用，检查配置里 `enabled` 是不是写了 `BTC_USDT`（下划线）。

### 4.2 K 线

```bash
gctcli gethistoriccandles --exchange Binance --pair BTC-USDT \
  --asset usdtmarginedfutures --granularity 3600 --rangesize 10
```

期望返回最近 10 根 1 小时 K 线（`time` / `open` / `high` / `low` / `close` / `volume` / `is_partial`）。

### 4.3 鉴权接口（验证 API Key）

```bash
gctcli getaccountbalances --exchange Binance --asset usdtmarginedfutures
```

期望返回你的 USDT 余额。**这一步失败就说明 Key 有问题**（权限、IP 白名单、Secret 错、合约账户未开通）。

```bash
gctcli getaccountbalances --exchange Binance --asset usdtmarginedfutures
```

### 4.4 技术指标（MACD / 均线）

```bash
gctcli technicalanalysis macd --exchange Binance --pair BTC-USDT \
```

## 5. 验证 REST 网关

`grpcProxyEnabled: true` 时，9053 端口提供 HTTPS + JSON：

**三条实测出来的坑**（与 gctcli 不同）：

1. 响应字段是 **camelCase**（`enabledExchanges`、`subsystemStatus`），不是 gctcli 输出的 snake_case
2. `pair` 是 **CurrencyPair 对象** `{delimiter, base, quote}`，**不是** `"BTC-USDT"` 字符串。传字符串会报
   `proto: syntax error (line 1:30): unexpected token "BTC-USDT"`
3. 每个端点的 HTTP 方法是固定的：`getticker`/`getorderbook`/`submitorder` 是 **POST**，
   `gethistoriccandles`/`gettechnicalanalysis`/`getallmanagedpositions` 是 **GET**。用错会返回 `{"code":12,"message":"Method Not Allowed"}`

```bash
# 1) 系统信息（GET）
curl -sk -u admin:'ChangeMeNow_2026' https://127.0.0.1:9053/v1/getinfo \
  | jq '{uptime, enabledExchanges, subsystemStatus}'

# 2) ticker（POST + pair 对象）
curl -sk -u admin:'ChangeMeNow_2026' -X POST https://127.0.0.1:9053/v1/getticker \
  -H 'Content-Type: application/json' \
  -d '{"exchange":"Binance","pair":{'"$PAIR_OBJ"'},"assetType":"usdtmarginedfutures"}' \
  | jq '{last, high, low, markPrice, indexPrice, lastUpdated}'

# 3) K 线（GET，start/end 必填，格式 "2006-01-02 15:04:05 MST"）
#    注意响应字段在**顶层**（.candle），不是 .data.candle
curl -sk -u admin:'ChangeMeNow_2026' -G https://127.0.0.1:9053/v1/gethistoriccandles \
  --data-urlencode 'exchange=Binance' \
  --data-urlencode 'pair.delimiter=-' --data-urlencode 'pair.base=BTC' --data-urlencode 'pair.quote=USDT' \
  --data-urlencode 'assetType=usdtmarginedfutures' \
  --data-urlencode 'timeInterval=3600000000000' \
  --data-urlencode 'exRequest=true' \
  --data-urlencode 'start=2026-10-01 00:00:00 UTC' \
  --data-urlencode 'end=2026-10-08 00:00:00 UTC' \
  | jq '{interval, count: (.candle|length), last: .candle[-1]}'
```

查任意端点的准确方法名和参数名：

```bash
jq -r '.paths | to_entries[] | .key as $p | .value | keys[] | "\(.|ascii_upcase)  \($p)"' gctrpc/rpc.swagger.json | sort -k2
jq -r '.paths."/v1/gethistoriccandles".get.parameters[].name' gctrpc/rpc.swagger.json
```

`-k` 是因为自签证书。认证失败会返回 401 + `WWW-Authenticate: Basic realm="restricted"`（`engine/rpcserver.go:243-254`）。

完整路由清单看 `gctrpc/rpc.swagger.json`，或用 `jq` 提取：

```bash
jq -r '.paths | keys[]' gctrpc/rpc.swagger.json | sort
```

## 6. 用 REST 网关做提交类操作

网关把变更类 RPC 映射成 POST：

```bash
# 查询全部本地跟踪仓位（GET，无参数）
curl -sk -u admin:'ChangeMeNow_2026' https://127.0.0.1:9053/v1/getallmanagedpositions | jq .

# 设置杠杆（POST）—— 注意字段名是 asset，不是 assetType；pair 是对象
curl -sk -u admin:'ChangeMeNow_2026' -X POST https://127.0.0.1:9053/v1/setleverage \
  -H 'Content-Type: application/json' \
  -d '{"exchange":"Binance","asset":"usdtmarginedfutures","pair":{'"$PAIR_OBJ"'},"leverage":5,"marginType":"isolated"}' | jq .
```

具体路径和字段名以 `gctrpc/rpc.swagger.json` 为准。

## 8. 关闭

前台直接 `Ctrl+C`。后台：

```bash
kill -INT "$(cat /tmp/gct.pid)"
```

或通过 RPC（需要 `grpcAllowBotShutdown: true`）：

```bash
gctcli shutdown --confirmshutdown
```

关闭时如果 `orderManager.cancelOrdersOnShutdown: true`，会先撤掉所有挂单（`OrderManager.CancelAllOrders`，`engine/order_manager.go:148`）。每个交易所最多等 10 秒优雅退出（`-exchangeshutdowntimeout`，默认 `time.Second*10`）。
