# 03 配置文件详解

本文逐字段说明 `config.json`，只保留币安 USDT 本位永续需要的部分，并说明每个字段**为什么**这么设。

## 1. 配置从哪来

仓库里的权威模板是 `config_example.json`（2972 行，`"name": "Skynet"`，`"version": 17`）。**没有** `config.DefaultConfig()` 这类生成函数，也没有首次运行自动落盘——必须手工复制。

```bash
mkdir -p ~/.gocryptotrader
cp config_example.json ~/.gocryptotrader/config.json
```

本目录提供的 [`config.binance-usdtm-futures.json`](config.binance-usdtm-futures.json) 已经按"仅币安永续"裁剪好（从 22 个交易所砍到 1 个），可以直接用：

```bash
cp docs/localDeploy/config.binance-usdtm-futures.json ~/.gocryptotrader/config.json
```

配置结构定义在 `config/config_types.go:92-123`：

```go
type Config struct {
    Name                 string                    `json:"name"`
    Version              int                       `json:"version"`
    DataDirectory        string                    `json:"dataDirectory"`
    EncryptConfig        int                       `json:"encryptConfig"`

    Database             database.Config           `json:"database"`
    Logging              log.Config                `json:"logging"`
    SyncManagerConfig    SyncManagerConfig         `json:"syncManager"`
    ConnectionMonitor    ConnectionMonitorConfig   `json:"connectionMonitor"`
    OrderManager         OrderManager              `json:"orderManager"`
    DataHistoryManager   DataHistoryManager        `json:"dataHistoryManager"`
    CurrencyStateManager CurrencyStateManager      `json:"currencyStateManager"`
    Profiler             Profiler                  `json:"profiler"`
    NTPClient            NTPClientConfig           `json:"ntpclient"`
    Currency             currency.Config           `json:"currencyConfig"`

    Portfolio            *portfolio.Base           `json:"portfolioAddresses"`
    Exchanges            []Exchange                `json:"exchanges"`

```

网上老教程里的 `core`、`webserver`、`gRPC`、`restAPI`、`notify`、`portfolioManager`、`futuresOrders`、`comms`、`strategies`、顶层 `currencyPairs` 这些键在 v17 里**都不存在**了。gRPC 在 `remoteControl.gRPC` 下，通知在 `communications` 下，交易对在 `exchanges[].currencyPairs` 下。

配置版本迁移由 `config/versions`（v0-v17，注册表 `config/versions/register.go`）负责，加载时自动升级到最新版（`config/config.go:1464-1466`）。所以拿旧配置也能启动，但建议直接用 v17。

## 2. 币安 API Key 申请

在配置之前先拿到 Key。

### 2.1 主网

1. 登录币安 → 头像 → **API 管理**
2. 创建 API Key，类型选 **系统生成的**（System generated），不要选 Ed25519（本项目 `credentialsValidator` 只要求 key+secret）
3. 权限勾选：
   - ✅ **读取**（Enable Reading）
   - ✅ **允许合约**（Enable Futures）—— 必须勾，否则合约接口全部 403
   - ✅ **允许现货及杠杆交易**（Enable Spot & Margin Trading）—— 只查余额的话可选
   - ❌ **允许提现**（Enable Withdrawals）—— **绝对不要勾**
4. **IP 限制**：填你本机的出口 IP（走代理就填代理的出口 IP）。不限制的话币安对部分接口会降权。
   本项目代码里**没有** IP 白名单相关处理，Key 的 IP 限制完全在币安侧生效。
5. 记下 `API Key` 和 `Secret Key`。Secret 只显示一次。

### 2.2 合约测试网

1. 打开 <https://testnet.binancefuture.com>
2. 用 GitHub / Google 账号登录（跟主网账号完全独立）
3. 右侧 **API Key** 面板 → 生成，测试网自动带全部权限、自动有模拟资金
4. 记下 Key 和 Secret

测试网的资金是假的，但**接口行为和主网一致**，是验证下单链路最安全的地方。切换方法见 [07-测试网与模拟交易](07-测试网与模拟交易.md)。

## 3. 顶层字段逐项说明

### 3.1 标识与加密

```json
"name": "BinanceUSDTMFuturesDev",
"version": 17,
"dataDirectory": "",
"encryptConfig": -1,
"globalHTTPTimeout": 15000000000
```

| 字段 | 说明 |
| --- | --- |
| `name` | 纯标识，日志和 RPC `GetInfo` 里显示 |
| `version` | 必须 `17`。低了会被自动迁移，高了报错 |
| `dataDirectory` | 空字符串 = 用系统默认（macOS `~/.gocryptotrader`）。填绝对路径可覆盖，且**不会**触发 dry-run |
| `encryptConfig` | `-1` 禁用加密 / `0` 启动时交互询问 / `1` 启用加密 |
| `globalHTTPTimeout` | 纳秒。`15000000000` = 15 秒 |

**`encryptConfig` 是个坑**：模板默认是 `0`，非 dry-run 启动时会**在 stdin 上问你"要不要加密配置文件"**（`config/config.go:1442-1447`）。后台运行、CI、`nohup` 场景下会直接卡死。开发期设 `-1` 最省心。

真要加密：设 `1`，程序会提示输入密钥，配置文件存成 `config.dat`（AES-GCM）。也可以用命令行工具离线加解密：

```bash
go run ./cmd/config encrypt -in ~/.gocryptotrader/config.json -out ~/.gocryptotrader/config.dat -key '你的密钥'
go run ./cmd/config decrypt -in ~/.gocryptotrader/config.dat -key '你的密钥'
```

加密实现见 `config/config_encryption.go`（`EncryptConfigData` l.103、`DecryptConfigData` l.149、`IsFileEncrypted` l.244）。

### 3.2 数据库

```json
"database": {
  "enabled": true,
  "verbose": false,
  "driver": "sqlite3",
  "connectionDetails": {
    "host": "", "port": 0, "username": "", "password": "",
    "database": "gocryptotrader.db", "sslmode": ""
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `enabled` | `false` 时程序仍能跑，只是日志里打一条 `database.ErrDatabaseSupportDisabled`（`engine/engine.go:316`）。**要存历史 K 线必须开** |
| `driver` | `sqlite3`（也接受 `sqlite`）或 `postgres`。常量见 `database/database_types.go:55-64` |
| `connectionDetails.database` | SQLite 下是**文件名**，最终路径 = `<datadir>/database/<文件名>`（`database/drivers/sqlite3/sqlite3.go:18-20`）。留空则用默认名 `gocryptotrader.db` |

模板里 `config_example.json` 是 `enabled: false` + `driver: "sqlite"`。本指南的模板改成 `enabled: true` + `driver: "sqlite3"`，因为 [06-数据库与历史K线](06-数据库与历史K线.md) 要落库。

只想跑实时行情、不需要历史数据落库的话，把 `enabled` 改回 `false` 即可，其它步骤不受影响。

**迁移必须手工跑**，引擎不会自动建表。见 06 文档。


| 字段 | 说明 |
| --- | --- |
| `level` | 竖线分隔的级别集合。排查问题加 `DEBUG` |
| `output` | `console`、`file` 或 `console\|file`。写文件时落到 `<datadir>/logs/<filename>` |
| `maxsize` | MB，超过就轮转 |

### 3.4 同步管理器（永续行情的命脉）

```json
"syncManager": {
  "enabled": true,
  "synchronizeTicker": true,
  "synchronizeOrderbook": true,
  "synchronizeTrades": false,
  "synchronizeContinuously": true,
  "timeoutREST": 15000000000,
  "timeoutWebsocket": 60000000000,
  "numWorkers": 4,
  "fiatDisplayCurrency": "USD",
  "pairFormatDisplay": { "uppercase": true, "delimiter": "-" },
  "verbose": false,
  "logSyncUpdateEvents": false,
  "logSwitchProtocolEvents": false,
  "logInitialSyncEvents": true
}
```

**这是币安永续能不能拿到实时行情的关键。** 因为币安合约**没有 WebSocket 支持**（`exchanges/binance/binance_wrapper.go:75-79` 显式对 `asset.Margin`、`asset.CoinMarginedFutures`、`asset.USDTMarginedFutures` 调 `DisableAssetWebsocketSupport`），所有 ticker / orderbook 只能靠 SyncManager 走 REST 轮询。

| 字段 | 说明 | 建议值 |
| --- | --- | --- |
| `enabled` | 关掉就没有持续行情，只能每次 RPC 现拉 | `true` |
| `synchronizeTicker` | 轮询最新价 | `true` |
| `synchronizeOrderbook` | 轮询深度 | `true`（下单前要看盘口） |
| `synchronizeTrades` | 轮询成交 | `false`（合约成交数据量大，开发期不需要） |
| `synchronizeContinuously` | 持续同步而非一次性 | `true` |
| `timeoutREST` | 纳秒。REST 数据超过这个时长没更新就尝试切 WS | `15000000000`（15s） |
| `timeoutWebsocket` | WS 超过这个时长没数据就切回 REST | `60000000000`（1m） |
| `numWorkers` | 并发 goroutine 数 | 交易对少就 `4`，默认 `15` |
| `pairFormatDisplay` | 日志/RPC 展示格式 | `-` 分隔，跟 gctcli 一致 |

结构定义 `config/config_types.go:155-171`，默认常量 `DefaultSyncerWorkers = 15`、`DefaultSyncerTimeoutREST = 15s`、`DefaultSyncerTimeoutWebsocket = 1m`（`config_types.go:41-45`）。

因为币安合约没 WS，`timeoutWebsocket` 实际不会触发切换，日志里不会出现协议切换事件——这是正常的。

命令行也能开：`-syncmanager`（默认 `false`，会覆盖配置里的 `false`；配置里已经是 `true` 就不需要）。

### 3.5 订单管理器（永续仓位追踪）

```json
"orderManager": {
  "enabled": true,
  "verbose": false,
  "activelyTrackFuturesPositions": true,
  "futuresTrackingSeekDuration": 604800000000000,
  "respectOrderHistoryLimits": true,
  "cancelOrdersOnShutdown": false
}
```

| 字段 | 说明 |
| --- | --- |
| `activelyTrackFuturesPositions` | 开启后本地维护合约仓位、未实现盈亏、资金费。`GetManagedPosition` / `GetAllManagedPositions` 依赖它 |
| `futuresTrackingSeekDuration` | 纳秒。回溯多久的历史来重建仓位。**必须 > 0**，否则订单管理器启动失败并报 `errInvalidFuturesTrackingSeekDuration`（`engine/order_manager.go:44-45`） |
| `respectOrderHistoryLimits` | 遵守交易所的历史订单查询窗口。币安是 7 天（`binance_wrapper.go:85` `MaximumOrderHistory: kline.OneDay * 7`） |
| `cancelOrdersOnShutdown` | 关闭程序时是否撤掉挂单。开发期 `false`，自动化跑策略时按需 |

模板里我设 `604800000000000` = 7 天，跟币安的历史窗口对齐；`config_example.json` 里是 `31536000000000000` = 365 天，会白拉一堆请求。

结构定义 `config/config_types.go:129-136`。

### 3.6 连接监视器与 NTP

```json
"connectionMonitor": {
  "preferredDNSList": ["223.5.5.5", "119.29.29.29"],
  "preferredDomainList": ["www.baidu.com", "www.cloudflare.com"],
  "checkInterval": 5000000000
},
"ntpclient": {
  "enabled": -1,
  "pool": ["pool.ntp.org:123"],
  "allowedDifference": 50000000,
  "allowedNegativeDifference": 50000000
}
```

理由见 [01-环境准备](01-环境准备.md) 第 4.3、5.1 节。要点：

- `connectionMonitor` 默认探测 google/cloudflare/facebook，国内会一直失败刷日志
- `ntpclient.enabled` 是**整数级别**（`-1` 禁用 / `0` 启动检查且不同步时**交互提问** / `1` 周期告警），设 `0` 会卡住无人值守启动
- `allowedDifference` 纳秒，`50000000` = 50ms

### 3.7 远程控制（gRPC / REST 网关）

```json
"remoteControl": {
  "username": "admin",
  "password": "ChangeMeNow_2026",
  "gRPC": {
    "enabled": true,
    "listenAddress": "127.0.0.1:9052",
    "grpcProxyEnabled": true,
    "grpcProxyListenAddress": "127.0.0.1:9053",
    "grpcAllowBotShutdown": false,
    "timeInNanoSeconds": false
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `username` / `password` | HTTP Basic Auth 凭据，gRPC 和 REST 网关共用。**默认是 `admin` / `Password`**（`config/config_types.go:72-73` 的 `DefaultGRPCUsername`/`DefaultGRPCPassword`），必须改 |
| `gRPC.enabled` | gRPC 服务开关。gctcli 依赖它 |
| `listenAddress` | 默认 `localhost:9052`。TLS 强制开启，证书自动生成到 `<datadir>/tls/` |
| `grpcProxyEnabled` | 开启 grpc-gateway，把同一批接口暴露成 HTTPS + JSON。**要求 gRPC 也开着**，否则报 "gRPC proxy cannot be enabled when gRPC is disabled"（`config/config.go:1604-1607`） |
| `grpcProxyListenAddress` | 默认 `localhost:9053` |
| `grpcAllowBotShutdown` | 允许通过 RPC 关停程序。开发期 `false` 防误操作 |
| `timeInNanoSeconds` | RPC 响应里时间用纳秒整数还是 RFC3339 字符串。`false` 更好读 |

服务实现 `engine/rpcserver.go:126-189`（`StartRPCServer`）、`191-241`（`startRPCRESTProxy`）。证书自动生成逻辑在 `engine/helpers.go:801+`（`CheckCerts`/`genCert`，ECDSA P-256，有效期 1 年）。

结构定义 `config/config_types.go:234-249`。

**开 REST 网关的价值**：可以用 `curl` + JSON 直接调所有接口，不用写 gRPC 客户端。OpenAPI 规范在 `gctrpc/rpc.swagger.json`。这在 `docs/llm-dev` 的方案里是 LLM 工具层的一个候选接入方式。

示例：

```bash
# getticker 是 POST，且 pair 必须是对象（不是 "BTC-USDT" 字符串）
curl -sk -u admin:'ChangeMeNow_2026' -X POST https://127.0.0.1:9053/v1/getticker \
  -H 'Content-Type: application/json' \
  -d '{"exchange":"Binance","pair":{'"$PAIR_OBJ"'},"assetType":"usdtmarginedfutures"}'
```

### 3.8 其它顶层字段

```json
"currencyStateManager": { "enabled": true, "delay": 60000000000 },
"dataHistoryManager": { "enabled": false, "checkInterval": 60000000000, "maxJobsPerCycle": 5, "maxResultInsertions": 0, "verbose": false },
"profiler": { "enabled": false, "listen_address": "localhost:8085" }
```

| 字段 | 说明 |
| --- | --- |
| `currencyStateManager` | 追踪币种充提/交易状态，下单前会调 `CanTradePair` 检查是否被 halt。`delay` 是刷新间隔 |
| `dataHistoryManager` | 历史数据落库任务调度器。**需要数据库**。要跑历史 K 线任务时改 `true`，详见 06 文档 |
| `profiler` | pprof 端点。性能排查时开 |

`communications`（slack / smsGlobal / smtp / telegram）默认全 `false`。想让下单成功/失败推送到 Telegram，把 `telegram.enabled` 设 `true` 并填 `token` 和 `targetChat`。订单管理器已经会往通信管理器推 `base.Event{Type:"order"}` 事件（`engine/order_manager.go:449-452`、`469-472`），开了就有通知。

`portfolioAddresses`、`bankAccounts` 跟永续无关，留空/默认即可。

## 4. 交易所配置（核心）

### 4.1 只留币安

`config_example.json` 里有 **22 个交易所全部 `enabled: true`**，启动时会挨个初始化、拉交易对，慢而且日志爆炸。三种处理：

1. **删掉其它交易所条目**（本目录模板已这么做，只留 Binance）
2. 把其它的 `"enabled"` 改成 `false`
3. 启动时用 `-exchanges binance` 覆盖（**会强制 dry-run**，`engine/engine.go:927-937`）

交易所名在 `exchanges/support.go:16-39` 里是小写 `"binance"`，但配置文件里写的是 `"Binance"`（大小写不敏感匹配）。

### 4.3 API 凭据

```json
"api": {
  "authenticatedSupport": true,
  "authenticatedWebsocketApiSupport": false,
  "credentials": { "key": "...", "secret": "..." },
  "credentialsValidator": { "requiresKey": true, "requiresSecret": true }
}
```

`credentials` 支持的字段（`config/config_types.go:303-312`）：`key`、`secret`、`clientID`、`subaccount`、`pemKey`、`otpSecret`、`tradePassword`、`pin`。币安只需要 `key` 和 `secret`。

**占位符陷阱**：如果 `authenticatedSupport: true` 但 key/secret 是空或者等于占位符字符串 `"Key"` / `"Secret"` / `"ClientID"`（常量在 `config_types.go:34-36`），程序会**静默降级成只读公共接口**，只打一条警告：

```text
exchange Binance authenticated API support disabled due to default/empty APIKey/Secret/ClientID values
```

（`config/config.go:943-966`）。启动后一定要在日志里确认这条**没有**出现。

如果 Key 校验失败（IP 不在白名单、权限不够、Key 无效），`engine/engine.go:866-882` 同样会禁用鉴权并告警。

`authenticatedWebsocketApiSupport` 对币安合约设 `false`——没有合约 WS。

### 4.4 urlEndpoints 与 features

`urlEndpoints` 的键名必须和代码里的端点常量对应。币安在 `SetDefaults()`（`binance_wrapper.go:185-196`）里设的默认值：

| 配置键 | 默认值 | 用途 |
| --- | --- | --- |
| `RestUSDTMarginedFuturesURL` | `https://fapi.binance.com` | **USDT 本位合约，本指南主角** |
| `RestCoinMarginedFuturesURL` | `https://dapi.binance.com` | 币本位合约 |
| `RestSpotURL` | `https://sapi.binance.com` | 现货 sapi |
| `RestSpotSupplementaryURL` | `https://api.binance.com` | 现货主 API |
| `EdgeCase1URL` | `https://www.binance.com` | 交易页面链接 |
| `WebsocketSpotURL` | `wss://stream.binance.com:9443/stream` | 现货 WS |

改这些值时基础层会打警告 `Config is overwriting default endpoint URL values from ... to ...`（`exchanges/exchange.go:793+`），非 HTTPS 还会额外告警。**切测试网就是改 `RestUSDTMarginedFuturesURL`**。

`features` 块：

```json
"features": {
  "supports": {
    "restAPI": true,
    "restCapabilities": {
      "tickerBatching": true,
      "autoPairUpdates": true,
      "fundingRateFetching": true
    },
    "websocketAPI": false
  },
  "enabled": {
    "autoPairUpdates": true,
    "websocketAPI": false,
    "saveTradeData": false,
    "tradeFeed": false,
    "fillsFeed": false
  },
  "subscriptions": []
}
```

**重要**：`features.supports` 里你写的值大部分会被代码覆盖。`Base.SetFeatureDefaults()`（`exchanges/exchange.go:120-147`）只把这 4 项从代码同步回配置：`AutoPairUpdates`、`REST`、`TickerBatching`、`Websocket`。其余能力（资金费率、K 线、下单、仓位等）由 `binance_wrapper.go:81-176` 的 `SetDefaults()` 声明，`GetSupportedFeatures()` 返回的是**代码里的** `b.Features.Supports`（`exchanges/exchange.go:380`），不是你配置里写的那份。

所以 `config_example.json` 里那个 `"fundingRateFetching": false` 是**装饰性的**——代码里是 `true`（`binance_wrapper.go:109`），运行时就是 `true`。

币安实际支持的能力（`binance_wrapper.go:81-176`）：

- REST 能力：TickerBatching、TickerFetching、KlineFetching、OrderbookFetching、AutoPairUpdates、AccountInfo、CryptoDeposit、CryptoWithdrawal、GetOrder(s)、CancelOrder(s)、SubmitOrder、DepositHistory、WithdrawalHistory、TradeFetching、UserTradeHistory、TradeFee、CryptoWithdrawalFee、MultiChainDeposits/Withdrawals、HasAssetTypeAccountSegregation、FundingRateFetching —— 全 `true`
- 合约能力（`FuturesCapabilities`，l.130-145）：`Positions: true`、`Leverage: true`、`CollateralMode: true`、`FundingRates: true`（频率 4h 和 8h）、`FundingRateBatching: {usdtmarginedfutures: true}`、`OpenInterest: {Supported: true}`
- K 线：支持日期区间和间隔；启用的间隔是 `1m,3m,5m,15m,30m,1h,2h,4h,6h,8h,12h,1d,3d,1w,1M`；`GlobalResultLimit: 1000`
- `MaximumOrderHistory`: 7 天
- 提现权限：`AutoWithdrawCrypto | NoFiatWithdrawals`
- WS 能力：现货才有；`FundingRateFetching` 在 WS 侧是 `false`（代码注释：`supported but not implemented // TODO when multi-websocket support added`，l.122）

`enabled.websocketAPI` 设 `false`（合约无 WS）。`subscriptions` 留空数组——默认订阅模板全是现货的（ticker / allTrades / candles@1m / orderbook@100ms，`binance_wrapper.go:170-175`），留着只会产生无效订阅。

`saveTradeData: false`（不往数据库写成交），`tradeFeed` / `fillsFeed` 同理。

### 4.5 currencyPairs（最容易出错的地方）

```json
"currencyPairs": {
  "bypassConfigFormatUpgrades": false,
  "pairs": {
    "spot":                { "assetEnabled": false, "enabled": "", "available": "", "...": "..." },
    "margin":              { "assetEnabled": false, "enabled": "", "available": "", "...": "..." },
    "coinmarginedfutures": { "assetEnabled": false, "enabled": "", "available": "", "...": "..." },
    "usdtmarginedfutures": {
      "assetEnabled": true,
      "enabled": "BTC_USDT,ETH_USDT",
      "available": "BTC_USDT,ETH_USDT,SOL_USDT,...",
      "requestFormat": { "uppercase": true },
      "configFormat":  { "uppercase": true, "delimiter": "_" }
    }
  }
}
```

结构定义 `currency/manager_types.go:10-39`。

#### 资产类型标识

币安支持 4 种（`binance_wrapper.go:38-59` 的 `defaultAssetPairStores`）：

| 资产标识字符串 | 含义 | 本指南 |
| --- | --- | --- |
| `spot` | 现货 | 关 |
| `margin` | 杠杆 | 关 |
| `coinmarginedfutures` | 币本位合约 | 关 |
| `usdtmarginedfutures` | **USDT 本位永续/交割合约** | **开** |

常量定义在 `exchanges/asset/asset.go:26-75`。**没有 `usdt_swap` 这个字符串**，传进去会被 `asset.New()` 拒绝并返回 `ErrNotSupported`（`asset.go:313`）。`perpetualswap`（别名 `swap`）是别的交易所用的，币安不认。

#### 三套格式，别搞混

| 格式 | USDT-M 永续的值 | 用在哪 |
| --- | --- | --- |
| `configFormat` | `BTC_USDT`（大写 + 下划线） | **配置文件里的 `enabled` / `available`** |
| `requestFormat` | `BTCUSDT`（大写 + 无分隔符） | 发给币安 API 的 `symbol` 参数 |
| `pairFormatDisplay` | `BTC-USDT`（大写 + 连字符） | gctcli 输入、RPC 展示 |

在配置的 `usdtmarginedfutures.enabled` 里写 `BTC-USDT` 会触发交易对一致性检查失败（`CheckPairConsistency`，`config/config.go:470`、`1008-1016`）。**必须写 `BTC_USDT`**。

格式转换在 `binance_wrapper.go:1828-1853`（`FormatSymbol` / `formatUSDTMarginedFuturesPair`）。

#### enabled 与 available 的区别

- `available`：交易所上**存在**的全部交易对。`autoPairUpdates: true` 时启动会自动刷新（`exchange.Bootstrap`，`exchanges/exchange.go:1787-1829`，走 `/fapi/v1/exchangeInfo`，只把 `ContractType == "PERPETUAL"` 的当成 base/quote 对，交割合约保留 `BTCUSDT_251226` 这种原名，`binance_wrapper.go:287-308`）
- `enabled`：你**实际要用**的子集。只有在这里的交易对才能查行情、下单

`available` 可以留空让程序自己填，也可以像模板那样预填一批。`enabled` 必须手写，逗号分隔。

#### 关掉其它资产的注意事项

配置校验有两条规则（`config/config.go:920-933`）：

- 如果一个交易所**所有**资产都 `assetEnabled: false`，整个交易所会被禁用
- 如果全部关掉，校验会**强制打开第一个**资产

所以至少要留一个 `assetEnabled: true`。本指南只留 `usdtmarginedfutures`。

`bypassConfigFormatUpgrades: false` 表示允许程序在加载时自动升级旧格式。保持 `false`。

## 7. 安全须知

- `docs/CODING_GUIDELINES.md:23` 明确写：**Never commit API keys, secrets, client IDs or a populated config.json**
- `~/.gocryptotrader/config.json` 在仓库外，不会被 git 跟踪。别把它复制进仓库目录
- gRPC 密码改掉默认的 `Password`
- 币安 API Key 一定要**禁提现** + **绑 IP**
- 配置里存明文 Key。要加密就用 `encryptConfig: 1` 或 `go run ./cmd/config encrypt`
