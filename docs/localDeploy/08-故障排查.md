# 08 故障排查

按"启动阶段 → 连接阶段 → 数据阶段 → 下单阶段"分组。每条给出**症状 / 根因 / 源码位置 / 解法**。

## 1. 启动阶段

### 1.1 `config.json file not found in ...`

**根因**：程序不会自动生成配置。查找顺序（`config/config.go:1366-1395`）：

1. `<可执行文件目录>/config.json`
2. `<可执行文件目录>/config.dat`
3. `<数据目录>/config.json`
4. `<数据目录>/config.dat`

**解法**：

```bash
mkdir -p ~/.gocryptotrader
cp docs/localDeploy/config.binance-usdtm-futures.json ~/.gocryptotrader/config.json
```

### 1.2 启动后卡住不动，没有任何输出

**根因**：两个交互式提问之一在等 stdin：

- `encryptConfig: 0` → 问"要不要加密配置文件"（`config/config.go:1442-1447`）
- `ntpclient.enabled: 0` 且时钟不同步 → 问怎么处理（`engine/engine.go:340-353`，`config.SetNTPCheck` `config/config.go:1255-1290`）

**解法**：两个都设成 `-1`：

```json
"encryptConfig": -1,
"ntpclient": { "enabled": -1 }
```

临时绕过：加 `-dryrun`（会跳过加密提问）。

### 1.3 `go build` 报 SQLite 相关编译错误

**根因**：`CGO_ENABLED=0`。

**解法**：

```bash
go env -w CGO_ENABLED=1
xcode-select --install     # macOS 需要 clang
go build
```

### 1.4 `go.mod requires go >= 1.27`

**解法**：`brew upgrade go` 或装 Go 1.27+。`go.mod:3` 声明 `go 1.27`。

### 1.5 订单管理器起不来：`errInvalidFuturesTrackingSeekDuration`

**根因**：`orderManager.activelyTrackFuturesPositions: true` 但 `futuresTrackingSeekDuration <= 0`（`engine/order_manager.go:44-45`）。

**解法**：设成正数纳秒值，例如 7 天 = `604800000000000`。

### 1.6 交易所被自动禁用

**根因**：`config/config.go:920-925`，交易所没有任何启用的资产类型时会被禁用。或者 `927-933`，所有资产都关时会强制打开第一个。

**解法**：确保 `currencyPairs.pairs.usdtmarginedfutures.assetEnabled: true`。

### 1.7 一堆别的交易所也在启动，日志爆炸

**根因**：`config_example.json` 里 22 个交易所全是 `enabled: true`。

**解法**：删掉其它条目，或全部设 `false`，或启动加 `-exchanges binance`（会触发 dry-run）。

## 2. 连接阶段

### 2.1 `exchange Binance authenticated API support disabled due to default/empty APIKey/Secret/ClientID values`

**根因**：`authenticatedSupport: true` 但 key/secret 为空或等于占位符 `"Key"` / `"Secret"` / `"ClientID"`（`config/config.go:943-966`，常量 `config_types.go:34-36`）。

**解法**：填真实凭据。检查：

```bash
jq '.exchanges[0].api.credentials' ~/.gocryptotrader/config.json
```

### 2.2 币安返回 `-1021 Timestamp for this request was outside of the recvWindow`

**根因**：本地时钟偏差。签名用 `time.Now().UnixMilli()`（`binance.go:755`），`recvWindow` 默认 5000ms（`binance.go:100`、`749-751`）。

**解法**：

```bash
# 测偏差
LOCAL=$(python3 -c 'import time;print(int(time.time()*1000))')
REMOTE=$(curl -s https://fapi.binance.com/fapi/v1/time | jq -r .serverTime)
echo "偏差 $((LOCAL - REMOTE)) ms"

# macOS 开自动对时
sudo systemsetup -setusingnetworktime on
```

NTP 子系统**只能告警不能修时钟**（`engine/ntp_manager.md:22`）。

### 2.3 币安返回 `-2015 Invalid API-key, IP, or permissions for action`

三种可能，逐一排查：

| 可能 | 检查方法 |
| --- | --- |
| Key 无效/Secret 错 | 重新生成，注意 Secret 只显示一次 |
| **IP 不在白名单** | 币安 API 管理页看 Key 的 IP 限制。走代理时白名单要填**代理的出口 IP**，不是你本机的 |
| 权限不够 | 必须勾"允许合约"（Enable Futures） |

代码侧没有任何 IP 白名单处理，Key 校验失败时 `engine/engine.go:866-882` 会禁用鉴权并告警。

查自己的出口 IP：

```bash
curl -s --proxy socks5://127.0.0.1:7890 https://api.ipify.org
```

### 2.4 币安返回 `-4003 / -4004 / 403 Forbidden`（合约接口）

**根因**：API Key 没开合约权限，或者合约账户没开通。

**解法**：币安 App/网页 → 合约 → 开通 USDT 本位合约账户；API Key 勾"允许合约"。

### 2.5 请求超时 / `context deadline exceeded`

**根因**：网络不通或 `httpTimeout` 太短。

**解法**：

```bash
# 直连测试
curl -sv --max-time 10 https://fapi.binance.com/fapi/v1/time
# 走代理测试
curl -sv --max-time 10 --proxy socks5://127.0.0.1:7890 https://fapi.binance.com/fapi/v1/time
```

配置代理（`exchanges[].proxyAddress`，由 `SetClientProxyAddress` 应用，`exchanges/exchange.go:79-96`），并把 `httpTimeout` 调到 30 秒（`30000000000` 纳秒）：

```json
"proxyAddress": "socks5://127.0.0.1:7890",
"httpTimeout": 30000000000
```

### 2.6 连接监视器一直报失败

**根因**：默认探测 `8.8.8.8` / `1.1.1.1` / `www.google.com` / `www.facebook.com`（`config_example.json:62-75`，`connchecker/connchecker.go:13-27`），国内直连不通。

**解法**：三选一

```bash
./gocryptotrader -connectivitymonitor=false
```

或改成国内可达目标（见 03 文档 §3.6），或确保代理能通这些域名。

**这个子系统失败不影响币安请求**，币安走自己的 HTTP 客户端。

### 2.7 日志出现 `Config is overwriting default endpoint URL values`

**含义**：你改了 `api.urlEndpoints`。切测试网时**这是预期的**；如果你以为在打主网，说明配错了。

来源：`exchanges/exchange.go:793+` 的 `SetAPIURL()`。非 HTTPS 会额外告警。

## 3. 数据阶段

### 3.1 `currency pair not enabled` / `pair not found`

**根因**：交易对格式写错，或者不在 `enabled` 列表里。

**三套格式**（`binance_wrapper.go:38-59`）：

| 场景 | 格式 | 例子 |
| --- | --- | --- |
| 配置文件 `enabled` / `available` | `configFormat`（大写 + `_`） | `BTC_USDT` |
| 发给币安 API | `requestFormat`（大写 + 无分隔符） | `BTCUSDT` |
| gctcli / RPC | `pairFormatDisplay`（大写 + `-`） | `BTC-USDT` |

在配置里写 `BTC-USDT` 会触发 `CheckPairConsistency` 失败（`config/config.go:470`、`1008-1016`）。

**解法**：

```bash
jq '.exchanges[0].currencyPairs.pairs.usdtmarginedfutures.enabled' ~/.gocryptotrader/config.json
gctcli pair get --exchange Binance --asset usdtmarginedfutures
```

运行时加交易对：

```bash
gctcli pair enable --exchange Binance --asset usdtmarginedfutures --pairs SOL-USDT
```

### 3.2 `asset type not supported` / `ErrNotSupported`

**根因**：写了 `usdt_swap`、`swap`、`perpetual` 这类不存在的资产标识。

**解法**：币安只认四个（`exchanges/asset/asset.go:26-75`）：`spot`、`margin`、`coinmarginedfutures`、`usdtmarginedfutures`。`asset.New()` 对未知字符串返回 `ErrNotSupported`（`asset.go:313`）。

### 3.3 `getticker` 返回 `no ticker data found`

**根因**：SyncManager 还没跑第一轮，或者没启用。

**解法**：

```bash
jq '.syncManager' ~/.gocryptotrader/config.json     # enabled 应为 true
gctcli getsubsystems                                 # 确认 sync_manager 在跑
```

等 15-30 秒再试。或者用 `-syncmanager` 强制开（会触发 dry-run）。

**币安合约没有 WebSocket**（`binance_wrapper.go:75-79` 对 `asset.USDTMarginedFutures` 调 `DisableAssetWebsocketSupport`），行情全靠 SyncManager 的 REST 轮询，所以有轮询周期的延迟是正常的。

### 3.4 `kline.ErrRequestExceedsExchangeLimits`

**根因**：单次请求的时间跨度超过 1000 根 K 线（`GlobalResultLimit: 1000`，`binance_wrapper.go:167`）。检查在 `Base.GetKlineRequest`（`exchanges/exchange.go:1482`，报错在 l.1535）。

**解法**：用 `gethistoriccandlesextended`，它会自动拆批（`kline.CalculateCandleDateRanges`，`exchanges/kline/kline.go:622`）：

```bash
gctcli gethistoriccandlesextended --exchange Binance --pair BTC-USDT \
  --asset usdtmarginedfutures --interval 3600 \
  --start "2025-01-01 00:00:00" --end "2026-01-01 00:00:00"
```

### 3.5 `errNotEnoughData`（算指标时）

**根因**：MACD 要求数据量 `>= slow + signal - 2`（`exchanges/kline/technical_analysis.go:251`）。默认 12/26/9 → 至少 33 根。

**解法**：拉长 `--start`，或减小 `--granularity`。

```bash
# 1 小时线，取最近一个月，肯定够
gctcli technicalanalysis macd --exchange Binance --pair BTC-USDT \
  --asset usdtmarginedfutures --granularity 3600 \
  --start "2026-01-01 00:00:00" --end "2026-02-01 00:00:00"
```

MACD 还要求 `fast < slow` 且都 > 0。

### 3.6 `errCandleDataNotPadded`

**根因**：对未填充缺口的数据做 `ConvertToNewInterval`（`exchanges/kline/kline.go:528`）。

**解法**：先用 `Extended` 版本拉全（`ProcessResponse` 会自动 `addPadding`，`exchanges/kline/request.go:146`）。

### 3.7 最后一根 K 线数据怪怪的

**根因**：它是未收盘的部分 K 线，`is_partial: true`，`ValidationIssues` 标为 `"Partial Candle"`（常量 `exchanges/kline/request.go:25`）。

**解法**：算指标前把最后一根去掉，或者接受它会随实时价格抖动。

### 3.8 请求的间隔币安不支持

**根因**：币安只启用 `1m, 3m, 5m, 15m, 30m, 1h, 2h, 4h, 6h, 8h, 12h, 1d, 3d, 1w, 1M`（`binance_wrapper.go:150-166`）。

**解法**：系统会尝试用 `ExchangeIntervals.Construct` 从更小的间隔合成（`exchanges/kline/kline.go:812-874`），比如 1h 可以由 2×30m 合成。合成不了就报错。gctcli 支持的 granularity 全集见 05 文档 §2.1。

### 3.9 限频 `-1003 Too many requests`

**根因**：超过币安权重限额。USDT-M 合约 2400 weight/min，下单 300 次/10s（`exchanges/binance/ratelimit.go:23-26`）。

**解法**：内置限频器默认开着（`-ratelimiter`，默认 `true`），**别关**。K 线权重按 limit 分档：≤100 根 = 1，≤500 = 2，≤1000 = 5，>1000 = 10（`binance_ufutures.go:183-222`）。

减少请求：开数据库 + `--db=true`，或用 DataHistoryManager 预拉。

## 4. 下单阶段

### 4.1 `order.ErrSubmitLeverageNotSupported`

**根因**：`order.Submit.Leverage` 不是 0 或 1（`binance_wrapper.go:793-795`）。币安不接受下单时带杠杆。

**解法**：单独设杠杆：

```bash
gctcli futures setleverage --exchange Binance --asset usdtmarginedfutures --pair BTC-USDT \
  --leverage 5 --margintype isolated
```

### 4.2 下单被拒：`ReduceOnly Order is rejected`

**根因**：下了 reduce-only 单但当前没有对应方向的持仓。

**解法**：先查仓位 `gctcli futures getmanagedposition ...`。注意 gctcli 的 `submitorder` 没有 `--reduceonly` flag，如果出现了这个错误说明是通过 REST 或代码传的 `ReduceOnly: true`（`binance_wrapper.go:934` 会转发这个字段）。

### 4.3 下单被拒：`PositionSideNotMatch` 之类

**根因**：币安账户开了**双向持仓（Hedge Mode）**，但本项目 wrapper 在 USDT-M 分支**不传 `positionSide`**（`binance_wrapper.go:896-940` 只映射 `order.Buy → "BUY"`、`order.Sell → "SELL"`）。

**解法**：切成单向持仓：

```bash
gctcli futures getcollateralmode --exchange Binance --asset usdtmarginedfutures
gctcli futures setcollateralmode --exchange Binance --asset usdtmarginedfutures --collateralmode one_way
```

（对应 `POST /fapi/v1/multiAssetsMargin`，`binance_ufutures.go:1028-1036`；只有 USDT-M 支持，`binance_wrapper.go:2188-2211`。**有持仓时改不了，先平仓。**）

### 4.4 下单被拒：精度/最小数量不合规

**根因**：数量或价格不符合合约规格。`OrderManager.Submit` 会先调 `exch.CheckOrderExecutionLimits(asset, pair, price, amount, orderType)`（`engine/order_manager.go:478-525`）。

**解法**：

```bash
# gctcli 未暴露该接口，直接查币安（filterType LOT_SIZE=数量步长, PRICE_FILTER=价格精度, MIN_NOTIONAL=最小名义额）
curl -s "https://fapi.binance.com/fapi/v1/exchangeInfo?symbol=BTCUSDT" | jq '.symbols[0].filters'
```

看 BTC-USDT 的 tick size 和 step size，按规格取整。限额数据由 `UpdateOrderExecutionLimits`（`binance_wrapper.go:1773` → `FetchUSDTMarginExchangeLimits`，`binance_ufutures.go:987`）在启动引导时刷新。

### 4.5 下单被拒：保证金不足

**解法**：

```bash
gctcli getaccountbalances --exchange Binance --asset usdtmarginedfutures
gctcli futures getallmanagedpositions       # 看已占用
```

降杠杆或减数量。逐仓模式下改保证金：

```bash
gctcli futures changepositionmargin --exchange Binance --asset usdtmarginedfutures --pair BTC-USDT --margintype isolated --originalallocatedmargin 100 --newallocatedmargin 200
```

（**只支持逐仓**，全仓返回 `ErrMarginTypeUnsupported`，`binance_wrapper.go:2239-2282`）

### 4.6 `modifyorder` 返回 `ErrFunctionNotSupported`

**根因**：币安 wrapper 没实现改单（`binance_wrapper.go:955-957`）。

**解法**：撤了重下。

```bash
gctcli cancelorder --exchange Binance --pair BTC-USDT --asset usdtmarginedfutures --orderid <id> --side BUY --type LIMIT --amount 0.001 --price 60000
gctcli submitorder ...
```

### 4.7 `setmargintype` 失败

**根因**：有持仓时币安不允许改保证金模式。

**解法**：先平仓。映射关系（`marginTypeToString`，`binance_wrapper.go:2285-2293`）：`isolated → "ISOLATED"`，`multi/cross → "CROSSED"`。

### 4.8 订单下出去了但 `getmanagedorders` 查不到

**根因**：订单管理器每 10 秒同步一轮（`orderManagerInterval = 10s`，`engine/order_manager_types.go:28`；`processOrders` l.651）。

**解法**：等 10 秒。或者用 `getorder` 直接查交易所：

```bash
gctcli getorder --exchange Binance --pair BTC-USDT --asset usdtmarginedfutures --orderid <id>
```

注意币安的历史订单查询窗口是 **7 天**（`MaximumOrderHistory: kline.OneDay * 7`，`binance_wrapper.go:85`），`respectOrderHistoryLimits: true` 会遵守它。超过 7 天的订单查不到。

### 4.9 `CanTradePair` 拦住了下单

**根因**：CurrencyStateManager 把该币种标成了 halt 状态（充提暂停、交易暂停等）。

**解法**：

```bash
gctcli getsubsystems
gctcli currencystate getall --exchange Binance    # 查币种状态
```

配置里 `currencyStateManager.enabled: false` 可以跳过这个检查（不建议）。

## 5. gRPC / gctcli

### 5.1 `connection refused` on 9052

**根因**：主程序没起，或 gRPC 关了，或换了端口。

**解法**：

```bash
lsof -nP -iTCP:9052 -sTCP:LISTEN
jq '.remoteControl' ~/.gocryptotrader/config.json
```

### 5.2 TLS 证书错误 / `x509: certificate signed by unknown authority`

**根因**：gctcli 默认读 `<datadir>/tls/cert.pem`（`cmd/gctcli/main.go`）。服务端和客户端用了不同的 datadir，或证书被重新生成过。

**解法**：

```bash
ls -l ~/.gocryptotrader/tls/
gctcli --cert ~/.gocryptotrader/tls/cert.pem info
```

证书自动生成逻辑在 `engine/helpers.go:801+`（`CheckCerts` / `genCert`，ECDSA P-256，1 年有效期）。也可以单独生成：`go run ./cmd/gen_cert`。

### 5.3 认证失败 / `Unauthenticated`

**根因**：用户名密码不对，或者全局参数写在了子命令后面。

**解法**：

```bash
# 全局参数必须在子命令前
gctcli --rpcuser admin --rpcpassword 'ChangeMeNow_2026' info

# 错
gctcli info --rpcuser admin
```

位置参数一律不接受（`cmd/gctcli/main.go:42-58`）。密码里有特殊字符要加引号。

改密码：`config.json` 的 `remoteControl.username` / `password`，重启生效。默认值是 `admin` / `Password`（`config/config_types.go:72-73`）。

### 5.4 布尔 flag 不生效

**根因**：gctcli 的布尔 flag 必须用 `=`（`cmd/gctcli/README.md:35-36`）。

```bash
# 正确
--sync=true  --db=true  --force=true
# 错误
--sync true
```

### 5.5 REST 网关 401

**根因**：Basic Auth 凭据不对，或者 `grpcProxyEnabled: false`。

**解法**：

```bash
jq '.remoteControl.gRPC' ~/.gocryptotrader/config.json
curl -sk -u admin:'ChangeMeNow_2026' https://127.0.0.1:9053/v1/getinfo
```

`grpcProxyEnabled` 需要 `gRPC.enabled` 也是 `true`，否则报 `gRPC proxy cannot be enabled when gRPC is disabled`（`config/config.go:1604-1607`）。认证实现在 `engine/rpcserver.go:243-254`。

### 5.6 网关端口被占

**解法**：改 `remoteControl.gRPC.grpcProxyListenAddress`。默认 `localhost:9053`（`config/config.go:1602`）。

## 6. 数据库

### 6.1 `no such table: candle`

**根因**：没跑迁移。**引擎不会自动建表。**

**解法**：

```bash
cd cmd/dbmigrate && go run . -command up
cd ../dbseed && go run .
```

迁移目录常量是相对路径 `../../database/migrations`（`database/database_types.go:33-34`），所以必须在 `cmd/dbmigrate` 下运行，或用 `-migrationdir` 显式指定。

### 6.2 `Database support is disabled`

**根因**：`database.enabled: false`。引擎仍能跑，只是日志里打一条 `database.ErrDatabaseSupportDisabled`（`engine/engine.go:316`）。

**解法**：改 `true` 并重启。

### 6.3 DataHistoryManager 任务不推进

**检查顺序**：

```bash
jq '.database.enabled, .dataHistoryManager.enabled' ~/.gocryptotrader/config.json
gctcli getsubsystems | grep -i data_history
gctcli datahistory getactivejobs
gctcli datahistory getajob --nickname <你的任务名>
```

DataHistoryManager **依赖数据库子系统**。任务详情里的 `Results` 字段会说明卡在哪。开 `verbose: true` 看细节。

### 6.4 SQLite 锁 / `database is locked`

**根因**：多个进程同时写同一个 SQLite 文件（比如主程序和 `dbmigrate` 同时跑）。

**解法**：先停主程序再跑迁移。数据量大就切 Postgres（见 06 文档 §11）。

## 7. 诊断工具箱

### 7.1 打开详细日志

```bash
./gocryptotrader -verbose -exchangeverbose -connectivitymonitor=false
```

`-exchangeverbose` 会打印完整的 HTTP 请求 URL、签名参数和响应体。**注意它触发 dry-run。**

或运行时改：

```bash
gctcli setloggerdetails --logger EXCHANGE --level DEBUG
```

或配置里 `"logging": { "level": "DEBUG|INFO|WARN|ERROR" }`，`exchanges[].verbose: true`。

### 7.2 直接 curl 币安，绕过程序

区分"是币安的问题还是程序的问题"：

```bash
# 公共接口，不需要签名
curl -s https://fapi.binance.com/fapi/v1/time | jq .
curl -s "https://fapi.binance.com/fapi/v1/klines?symbol=BTCUSDT&interval=1h&limit=5" | jq .
curl -s "https://fapi.binance.com/fapi/v1/ticker/price?symbol=BTCUSDT" | jq .
curl -s https://fapi.binance.com/fapi/v1/exchangeInfo | jq '.symbols | length'
```

公共接口通、鉴权接口不通 → Key/IP/权限问题。

### 7.3 查交易所信息

```bash
gctcli getexchangeinfo --exchange Binance
```

返回启用的资产、交易对数量、端点 URL、`useSandbox` 状态等。确认端点是 `fapi.binance.com`（主网）还是 `testnet.binancefuture.com`（测试网）。

### 7.4 查子系统状态

```bash
gctcli getsubsystems
gctcli getinfo
```

对应 `Engine.GetSubsystemsStatus()`（`engine/helpers.go:75-90`）。

### 7.5 pprof

```json
"profiler": { "enabled": true, "listen_address": "localhost:8085" }
```

```bash
make profile_cpu      # 连 localhost:9050（Makefile:7 的 GCTLISTENPORT）

```

或直接：

