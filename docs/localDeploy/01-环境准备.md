# 01 环境准备

本文覆盖在 macOS（Apple Silicon）本地把 GoCryptoTrader 跑起来所需的全部前置条件。Linux 步骤基本一致，Windows 差异在文末单独说明。

## 1. 硬性依赖

| 依赖 | 版本要求 | 检查命令 | 依据 |
| --- | --- | --- | --- |
| Go | **1.27 或更高** | `go version` | `go.mod:3` 声明 `go 1.27` |
| Git | 任意近期版本 | `git --version` | 拉取源码 |
| make | 任意 | `make --version` | `Makefile` 定义了 `build`/`check`/`lint` 等目标 |
| gcc / clang | 系统自带 | `cc --version` | SQLite 驱动需要 cgo |

Go 1.27 是硬要求。低版本会在 `go build` 阶段直接报 `go.mod requires go >= 1.27`。

安装（macOS，用 Homebrew）：

```bash
brew install go
go version    # 期望输出 go1.27.x 或更高
```

### 1.1 cgo 必须开启

数据库默认驱动是 SQLite（`database.enabled=true` + `driver: "sqlite3"`），走 cgo。确认：

```bash
go env CGO_ENABLED    # 期望 1
```

如果是 `0`：

```bash
go env -w CGO_ENABLED=1
```

Xcode 命令行工具（提供 clang）：

```bash
xcode-select --install
```

## 4. 网络与代理（国内环境重点）

币安的全部端点在中国大陆默认不可直连：

| 用途 | 域名 | 协议 |
| --- | --- | --- |
| USDT 本位合约 REST | `fapi.binance.com` | HTTPS 443 |
| 现货 REST | `api.binance.com` | HTTPS 443 |
| 现货补充 REST（sapi） | `sapi.binance.com` | HTTPS 443 |
| 币本位合约 REST | `dapi.binance.com` | HTTPS 443 |
| 现货 WebSocket | `stream.binance.com:9443` | WSS |

### 4.1 三种配代理的方式

#### 方式 A：配置内按交易所设代理（推荐）

在 `config.json` 的 Binance 条目里加：

```json
"proxyAddress": "socks5://127.0.0.1:7890"
```

由 `exchanges/exchange.go:79-96` 的 `SetClientProxyAddress` 应用，只影响币安这一个交易所的 HTTP 客户端。**不会**触发 dry-run。

#### 方式 B：命令行全局代理

```bash
./gocryptotrader -httpproxy "socks5://127.0.0.1:7890"
```

注意：`-httpproxy` 和 `-globalhttpproxy` 都会**强制进入 dry-run 模式**（`engine/engine.go:963-965`），配置改动不会回写。开发期无所谓，但要知道这个副作用。

#### 方式 C：环境变量透明代理

```bash
export HTTPS_PROXY=http://127.0.0.1:7890
export HTTP_PROXY=http://127.0.0.1:7890
./gocryptotrader
```

Go 的 `http.Transport` 默认读这两个变量。这种方式对 gocryptotrader 完全透明，也不会触发 dry-run。

### 4.2 连通性自检

启动前先确认能通：

```bash
# 直连测试（应返回服务器时间戳）
curl -s https://fapi.binance.com/fapi/v1/time

# 走代理测试
curl -s --proxy socks5://127.0.0.1:7890 https://fapi.vision/fapi/v1/time 2>/dev/null || \
curl -s --proxy socks5://127.0.0.1:7890 https://fapi.binance.com/fapi/v1/time
```

返回类似 `{"serverTime":1759000000000}` 即为通。

### 4.3 连接监视器（Connection Monitor）会误报

`connectionMonitor` 子系统每 1 秒探测一次下列目标（`config_example.json:62-75`，默认值见 `connchecker/connchecker.go:13-27`）：

```json
"preferredDNSList": ["8.8.8.8", "8.8.4.4", "1.1.1.1", "1.0.0.1"],
"preferredDomainList": ["www.google.com", "www.cloudflare.com", "www.facebook.com"]
```

国内直连这些目标会失败，日志里刷连接异常，但**不影响币安请求**（币安走自己的 HTTP 客户端 + 代理）。三种处理：

1. 启动时关掉：`./gocryptotrader -connectivitymonitor=false`
2. 改成国内可达目标（本目录的配置模板已这么做了）：

   ```json
   "connectionMonitor": {
     "preferredDNSList": ["223.5.5.5", "119.29.29.29"],
     "preferredDomainList": ["www.baidu.com", "www.cloudflare.com"],
     "checkInterval": 5000000000
   }
   ```

3. 在 `proxyAddress` 生效的前提下保持默认（代理能通 google 时可行）

`checkInterval` 单位是纳秒，`5000000000` = 5 秒。

## 5. 系统时钟

币安的签名请求用本地时钟生成 `timestamp`，默认 `recvWindow = 5000` 毫秒（`exchanges/binance/binance.go:100`、`749-762`）。本地时钟偏差超过 5 秒，所有鉴权接口返回 `-1021 Timestamp for this request was outside of the recvWindow`。

检查本机与币安服务器时间差：

```bash
LOCAL=$(date +%s%3N 2>/dev/null || python3 -c 'import time;print(int(time.time()*1000))')
REMOTE=$(curl -s https://fapi.binance.com/fapi/v1/time | jq -r .serverTime)
echo "本地=$LOCAL 服务器=$REMOTE 偏差=$((LOCAL - REMOTE)) ms"
```

macOS 开启自动对时：

```bash
sudo systemsetup -setusingnetworktime on
sudo systemsetup -setnetworktimeserver time.apple.com
```

### 5.1 NTP 子系统会阻塞启动

`ntpclient.enabled` 是个**整数级别**，不是布尔（`engine/ntp_manager.md:29`）：

| 值 | 行为 |
| --- | --- |
| `-1` | 完全禁用 |
| `0` | 启动时检查一次；**时钟不同步时在 stdin 上交互式提问**（`engine/engine.go:340-353`） |
| `1` | 周期性告警 |

级别 `0` 会导致无人值守启动卡住。开发环境建议直接设 `-1`，或者在能正常对时的机器上保留 `0`。注意 NTP 子系统**只能告警，不能修时钟**（`engine/ntp_manager.md:22`）。

## 6. 数据目录

| 平台 | 默认路径 | 依据 |
| --- | --- | --- |
| macOS / Linux | `$HOME/.gocryptotrader` | `common/common.go:366-385` |
| Windows | `%APPDATA%\GoCryptoTrader` | 同上 |

目录结构（`docs/FILES.md:31-47`）：

```text
~/.gocryptotrader/
├── config.json          # 或加密后的 config.dat
├── currency.json        # 币种元数据缓存，自动生成
├── database/
│   └── gocryptotrader.db    # SQLite（database.enabled=true 时）
├── logs/
│   └── log.txt          # logging.output 含 "file" 时
└── tls/
    ├── cert.pem         # gRPC 自签证书，首次启动自动生成
    └── key.pem
```

创建目录：

```bash
mkdir -p ~/.gocryptotrader
ls -la ~/.gocryptotrader
```

覆盖方式有两种：

- 配置里写 `"dataDirectory": "/path/to/dir"`（`config.GetDataPath`，`config/config.go:1726-1734`）
- 命令行 `-datadir /path/to/dir`，**但这会强制 dry-run**（`engine/engine.go:137-144`，日志会打 `Command line argument '-datadir' induces dry run mode.`）

## 7. 配置文件查找顺序

`config.GetFilePath`（`config/config.go:1366-1395`）按下列顺序找，找到即停：

1. `<可执行文件所在目录>/config.json`
2. `<可执行文件所在目录>/config.dat`
3. `<数据目录>/config.json`
4. `<数据目录>/config.dat`

都找不到就报错退出。**不会自动生成**。

一个容易踩的坑：如果在仓库根目录（可执行文件 `./gocryptotrader` 所在处）放了 `config.json`，它优先级最高，会被自动迁移进数据目录（`migrateConfig`，`config/config.go:1400-1421`）。想统一管理就只在 `~/.gocryptotrader/` 放。

显式指定：

```bash
./gocryptotrader -config /absolute/path/to/config.json
```

## 8. 端口占用检查

| 端口 | 用途 | 默认绑定 |
| --- | --- | --- |
| 9052 | gRPC 服务 | `localhost` |
| 9053 | gRPC REST 网关（HTTPS） | `localhost` |
| 8085 | pprof（`profiler.enabled=true` 时） | `localhost` |
| 9050 | `make profile_heap` / `profile_cpu` 的目标端口 | — |

```bash
lsof -nP -iTCP:9052 -sTCP:LISTEN
lsof -nP -iTCP:9053 -sTCP:LISTEN
```

有占用就改 `remoteControl.gRPC.listenAddress`。

## 9. Windows 差异

- 数据目录：`%APPDATA%\GoCryptoTrader\config.json`
- 构建产物是 `gocryptotrader.exe` / `gctcli.exe`
- 代理用 `HTTP_PROXY` / `HTTPS_PROXY` 环境变量最省事
- 路径分隔符在配置里用正斜杠 `/`
