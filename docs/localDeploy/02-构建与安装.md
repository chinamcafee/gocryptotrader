# 02 构建与安装

## 1. 两个必须构建的产物

| 产物 | 命令 | 输出位置 | 作用 |
| --- | --- | --- | --- |
| `gocryptotrader` | `go build` | 仓库根目录 | 主守护进程，跑引擎 + gRPC 服务 |
| `gctcli` | `go build ./cmd/gctcli` | `./gctcli` | gRPC 命令行客户端，所有操作的入口 |

主程序入口是**仓库根目录的 `main.go`**，不是 `cmd/gocryptotrader/main.go`（后者不存在）。模块名 `github.com/thrasher-corp/gocryptotrader`（`go.mod:1`）。

```bash
cd /Users/changzechuan/TradeCryptoCoinProjects/gocryptotrader

go build
go build ./cmd/gctcli

ls -lh gocryptotrader gctcli
```

首次构建约 1-3 分钟（要编译 SQLite 的 cgo 部分）。

## 2. Makefile 目标

`Makefile` 里的目标（`make help` 不存在，直接看文件）：

| 目标 | 实际命令 | 用途 |
| --- | --- | --- |
| `make build` | `go build -ldflags "-w -s"` | 构建主程序，去掉符号表和调试信息，体积小 |
| `make install` | `go install -ldflags "-w -s"` | 装到 `$GOPATH/bin` |
| `make test` | `go test $(RACE_FLAG) -coverprofile=coverage.txt -covermode=atomic ./...` | 全量测试 |
| `make lint` | 安装 `golangci-lint v2.13.2` 后运行 | 静态检查 |
| `make misc_checks` | `bash ./scripts/misc_checks.sh` | 杂项检查 |
| `make markdownlint` | `npx markdownlint-cli2@0.23.2` | Markdown 检查 |
| `make check` | `lint misc_checks markdownlint test` | 提交前全量检查 |
| `make fmt` | `gofmt -s -w .` | 格式化 |
| `make gofumpt` | `gofumpt -l -w .` | 更严格的格式化 |
| `make sonic` | `go build -ldflags "-w -s" -tags "sonic_on"` | 用 Sonic JSON 库构建 |
| `make udecimal` | `go build -ldflags "-w -s" -tags "udecimal_on"` | 用 udecimal 替代 shopspring/decimal |
| `make gen_db_models` | sqlboiler 生成模型（`DRIVER ?= psql`） | 改数据库 schema 后用 |
| `make lint_configs` | 用 jq 按名称排序配置里的 exchanges | 改 `config_example.json` 后用 |
| `make profile_heap` / `make profile_cpu` | pprof 连 `localhost:9050` | 性能分析 |

日常只需要：

```bash
make build                 # 构建主程序（-w -s）
go build ./cmd/gctcli      # 构建 CLI（Makefile 没有单独目标）
```

## 3. 可选 build tag

`README.md:119-156` 记录了两个可选标签：

### 3.1 `sonic_on`

用 [Sonic](https://github.com/bytedance/sonic) 替代标准库 JSON，解析更快。

```bash
go build -tags "sonic_on"
```

### 3.2 `udecimal_on`

用 `udecimal` 替代 `shopspring/decimal`。README 明确列出了行为差异（舍入、精度处理不完全一致），**开发期不建议开**，除非要专门做精度对比。

```bash
go build -tags "udecimal_on"
```

两个标签可以同时开。默认（不带标签）走标准库 JSON + shopspring/decimal，这是最稳妥的组合。

## 4. 其它命令行工具

`cmd/` 下还有一批工具，按用途分：

| 工具 | 构建命令 | 用途 |
| --- | --- | --- |
| `cmd/config` | `go build ./cmd/config` | 配置升级/降级/加解密：`upgrade\|downgrade\|encrypt\|decrypt`，flag 有 `-in -out -edit -key -version` |
| `cmd/dbmigrate` | `go build ./cmd/dbmigrate` | 数据库迁移，见 [06-数据库与历史K线](06-数据库与历史K线.md) |
| `cmd/dbseed` | `go build ./cmd/dbseed` | 往数据库灌交易所/交易对种子数据 |
| `cmd/gen_cert` | `go build ./cmd/gen_cert` | 单独生成自签 TLS 证书 |
| `cmd/gen_otp` | `go build ./cmd/gen_otp` | 生成 TOTP 验证码（交易所开了 OTP 时用） |
| `cmd/gen_sqlboiler_config` | `go build ./cmd/gen_sqlboiler_config` | 生成 sqlboiler 配置 |
| `cmd/documentation` | `go run ./cmd/documentation` | 从模板重新生成文档 |
| `cmd/exchange_template` | `go build ./cmd/exchange_template` | 新交易所脚手架 |

本指南用到的是 `gctcli`、`dbmigrate`、`dbseed`、`config`。一次性都建好：

```bash
go build ./cmd/gctcli ./cmd/dbmigrate ./cmd/dbseed ./cmd/config
ls -lh gctcli dbmigrate dbseed config
```

## 5. 回测器（可选）

回测器是**独立程序**，有自己的入口 `backtester/main.go` 和 CLI `backtester/btcli`：

```bash
go build ./backtester          # 产出 backtester 二进制
go build ./backtester/btcli    # 产出 btcli
```

回测器能作为常驻 gRPC 服务跑，并且支持**实盘数据 + 真实下单**模式（`LiveData{RealOrders: true}`，`backtester/config/strategyconfig_types.go:192-206`）。它是本仓库唯一带策略框架的地方，`docs/llm-dev` 的技术方案会把它作为自动决策的落点之一。

本指南主线不依赖回测器，先跳过。

## 6. 验证构建产物


## 7. 运行测试（可选，验证环境健康）

```bash
go test ./exchanges/binance/... -count 1
```

大部分测试是离线的（用 `testdata/` 里的固定响应）。带 `-race` 的全量测试：

```bash
make test
```

耗时较长（数分钟）。只想快速确认环境没问题，跑 binance 包就够。

## 8. Docker 方式（可选）

`Dockerfile` 用 `golang:1.27` 构建两个二进制，把 `config_example.json` 复制到 `/root/.gocryptotrader/config.json`，`EXPOSE 9050-9053`。

```bash
docker build -t gocryptotrader .
docker run --rm -it \
  -p 9052:9052 -p 9053:9053 \
  -v ~/.gocryptotrader:/root/.gocryptotrader \
  gocryptotrader
```

`docker-compose.yml` 映射 `9052:9052` 和 `9053:9053`。

容器里访问宿主机代理要用 `host.docker.internal` 而不是 `127.0.0.1`：

```json
"proxyAddress": "socks5://host.docker.internal:7890"
```
