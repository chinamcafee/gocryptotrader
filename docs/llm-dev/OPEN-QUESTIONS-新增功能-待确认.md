# OPEN-QUESTIONS · 新增功能（筛选/批量决策/持仓复核）待确认汇总

> 2026-10-15 立。三项新需求（对话筛选合约、批量开仓决策、持仓复核决策）落地中的口径问题。
> 分类：**A 类=已按"建议默认"落地、不阻塞主线，供你拍板确认或改**；**B 类=真阻塞，未拍板前跳过对应小项**。

## A 类（已按建议默认落地——改动只影响一处实现点）

### A1. "净资金流入/流出"的口径

- **建议默认（已实现）**：`netFlow24h` = 24h 窗口 **taker 主动买入报价额 − 主动卖出报价额**（币安 `/futures/data` taker 买卖量端点，逐符号读）；同时暴露 `takerBuyRatio24h`。正=净流入、负=净流出。
- 备选口径：① 未平仓量（OI）增量（另有"新资金进场"语义，但需两时点采样，暂不可缓存化）；② 现货+合约合并视角（跨市场，超出本平台范围）。
- 影响：切换口径=改一个 metric 实现（registry 一行）。

### A2. "4h/48h 涨跌走势"的定义

- **建议默认（已实现）**：**收盘对收盘涨跌幅**——`change4h`/`change48h` = 最新已收盘 1h K 线收盘价 ÷ N 根前收盘 − 1（缓存切片，零权重）。
- 备选：斜率回归、连续同向根数、区间高低点位置。
- 影响：换定义=加注册表新指标（不覆盖旧名）。

### A3. 批量决策规模与预算

- **建议默认（已实现）**：单批 ≤10 市场（`llm.batch.maxMarkets` 可配）、**串行**执行、每市场仍走既有预算预约与全部门禁；批次作业为内存态（进程重启丢作业壳，已产出的决策记录不受影响）。
- 备选：并发 2-3（更快但预算与限频抖动大）；落库作业表（跨重启续跑，增值但增迁移）。

### A4. 批量决策是否自动执行（下单）

- **建议默认（已实现）**：**仅生成决策记录**（与现有 trigger/preview 同级：RPC 路径结构性不下单）；实际执行走已有的模式桥（PAPER/LIVE 自动链）或待人工确认流。
- 备选：批量裁决 ALLOW 时直接经订单桥提交（涉及真金白银的执行语义，若需要请明示——届时按 decisions/02 的单型与现有风控链扩展，不替默认）。

### A5. GUI 批量决策绑定的策略版本

- **建议默认（已实现）**：自动选"当前**活跃审批**（账号+网络匹配、版本 FROZEN、配对 READY）"的策略版本；多版本在 GUI 显式下拉选择；无活跃审批 → 起批 fail-closed 拒绝。
- 备选：绑定"上次使用"版本；或每批必须手工选择。

### A6. 持仓复核的"自开仓窗口"

- **建议默认（已实现）**：开仓时刻取本地 intents 表最近一行 `FILLED/PARTIALLY_FILLED`；读不到时以 48h 窗口兜底并在决策消息里如实标注"兜底窗口"（不静默冒充）。
- 备选：以 venue 成交明细为准（需新增逐符号成交历史读面）。

### A7. T2（逐符号按需读）覆盖面

- **建议默认（已实现）**：需要 `netFlow24h` 等的筛选按 **quoteVolume 前 100** 扫描（`screener.flowScanLimit` 可配）；超限市场该指标记 `null`，依赖它的 criteria 排除并计数上报"不冒充 0"。
- 备选：全 588 逐符号扫（权重与延迟不可接受，不建议）；或轮转分片扫（复杂，暂缓）。

### A8. 决策方向（"开多建仓 / 开空建仓"）由谁决定

- **建议默认（已实现）**：**方向由分析链产出**——模型在策略语境下输出 `OPEN_LONG`/`OPEN_SHORT`（候选契约限定），Jev 复核与硬风控照常把关；GUI 触发批量时**不指定方向**，只选市场与版本。理由：方向判断正是 LLM×Jev 决策系统的核心职能；用户在 GUI 强制方向等于绕过分析直接构造候选，与安全边界（候选只能由分析产出）冲突。
- 备选（如需）：GUI 增加"方向意图"下拉（开多/开空/听模型），非默认项仅作**分析提示**注入用户消息上下文（模型仍可给出 HOLD/反向，不硬约束）——若你需要"我指定这批做多"的语义，请指出，届时按此备选落地（不阻塞现链）。

### A9. "推荐列表"联动启用的触发边界（追加四原则之 2/3）

- **建议默认（设计已定，见 15 号文 §2.2）**：纳入/移出是**用户的显式 GUI 动作**（筛选页/覆盖页按钮）→ 一步完成"启用/禁用 + RefreshMarkets + 审计 + 通知"；**不是"筛选命中即自动全启用"**。理由：筛选条件随时变化，命中即改交易所配置会把探索性筛选变成配置写动作，风险与噪音都大。
- 备选（如需）：命中即自动启用全部推荐行——若你要这个语义请指出（改实现单点：在批量/筛选完成处调用同一端点）。

### A10. 全量扫描的发生时机（追加四原则之 1）

- **建议默认（设计已定，见 15 号文 §2.1）**：**筛选触发时**按需全量——T0 用已全量入库的批量 ticker 缓存（零新增请求）；T1/T2 对未启用市场按需 read-through（数据经 exchange wrapper 自带限速器，"远不超过 QPS"由此成立），结果回灌缓存；**常驻轮询仍只覆盖启用集合**（成本模型不变）。
- 备选：常驻全市场 K 线轮询（权重与存储占用大、偏离低频策略偏好，不建议）。
