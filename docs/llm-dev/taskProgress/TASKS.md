### 0.1 ✅ proto 工具链已校准（2026-10-11，session-24 收尾）

**根因（实测）**：本机插件版本与 `go.mod` tool 块**完全一致**（`~/go/bin/buf` 1.73.0 / `protoc-gen-go` v1.36.12 /
`protoc-gen-go-grpc` 1.6.2 / `protoc-gen-grpc-gateway` v2.31.0 / `protoc-gen-openapiv2` v2.31.0，须
`export PATH="$HOME/go/bin:$PATH"`）。不幂等的原因是**提交的生成文件出自更旧插件**：`rpc_grpc.pb.go` 头部
仍写 v1.6.1（diff 恰 2 行 = 版本注释）；`rpc.pb.gw.go` 的 336 行**全部是同一 reorder 模式**——每处只有
`req.Body` drain 相对 `ParseForm`/`PopulateQueryParameters` 的位置变化（旧 gateway 把 drain 放前面），
逐行核查无第二种差异形状。`rpc.pb.go` 与 swagger 零差异（它们的提交版本本来就对）。

**校准动作**：备份后按 go.mod 版本重新生成（`cd gctrpc && buf generate`）——一次性对齐 diff = 2 文件 /
+169−169。**建议把这次「仅重新生成」单独一个提交**（message 注明 protoc-gen-go-grpc 1.6.1→1.6.2、
grpc-gateway →v2.31.0）。

**幂等验收**：`buf generate` 连跑两次，`git diff gctrpc | shasum` = `80497e7459dc694c025d64122999e68b36524f1b` 两次完全一致；
`go build ./...` 通过。**2026-10-11 追加 6 个 LLM RPC（M3-05）后再验收：哈希 `95883d6fc586630c0e9d04f19d9fc90102023979` 两次一致；再追加 `LLMChatStream`（M3-07）后 `9bb0bb2d680c12931d24572dd527247bced17ebd` 两次一致——新增端点确实是纯增量 diff。**

**解锁**：`M1-14`、`M3-05`、`M4-15`、`M5-14`、`M5-17`、`W1-07` 及全部 `/v1/llm/*` 端点。

`M7`（Web UI）在 `docs/llm-dev/11` 中已列为里程碑，其工作内容**就是 W 组**，故不重复计权（见 W 组）。`M8`（LIVE）依赖用户资金与决策，不计入本清单权重，作为 `M6` 之后的独立阶段。
