## 2. 备份集定义（生产口径）

必须一起备份、缺一不可：

1. **vault 目录**（默认 `<datadir>/llm-vault`）：`vault-private.pem`（包裹钥匙对——**泄露它等于泄露全部历史密钥的包裹层**，权限 600）、`vault-public.pem`、`secrets/*.json`（逐条密钥密文）、`conversation-key.bin`（会话加密钥匙，首次使用聊天时铸出，**永不再生**）。
2. **数据库**：SQLite = 干净关闭后的单文件（演练口径）；PostgreSQL = `pg_dump` 逻辑备份（见 §4）。
3. **配置文件**：`config.json`（LLM 段、交易所段；加密配置则同时保住其加密口令来源）。

## 3. 操作手册：备份与恢复（生产）

1. **备份**：停写（或选低峰）→ 备份 vault 目录（保持 600/700 权限）→ 停 SQLite 连接后拷 `.db` 文件（PostgreSQL 用 `pg_dump -Fc`）→ 拷 `config.json` → 三样**同一批次**归档（推荐同一压缩包，防"三缺一"）。
2. **恢复**：新机装同版本（或更新版本）二进制 → 解开归档到新 datadir → 确认 vault 目录权限 600/700 → 起 bot。
3. **验收点**（与演练第 3–7 步对应）：日志无迁移错误；健康页：配对 READY（或可重新探针）、用量页有数、对话页历史可读；`gctcli llm readiness` 各门可评估。
4. **红线**：vault 目录与数据库**分开保管传输**（拿到了库还需要 vault 才解得开；两者同行等于把保密边界打回明文）；恢复环境确认磁盘加密在位。

## 4. 边界与诚实状态

- 演练在**同机新进程 + 全新目录树**上验证（进程与路径边界都是真的；不是真实双机/跨 OS）。跨 OS 的差异面（路径分隔、文件权限模型）未覆盖——留待真实环境迁移时按上表复核。
- 本机演练用 **SQLite**；生产若用 PostgreSQL，恢复链多一步 `pg_restore`，**这一条未在演练中执行**（本机无生产库可演），已在 §3 手册中单列。
- 机器 B 的验证是**只读 + 迁移**：未声称在 B 上执行过新的写路径（下单/结算）——那属于恢复后的持续运行，与 M6-06 崩溃恢复同门但不同命题。
- 币安交易所 Key（`exchanges.binance` 段）随 `config.json` 同路径备份；其**轮换**在 M6-07 记录中走决策/凭据门，与本项的"搬迁保存"是两件事。
