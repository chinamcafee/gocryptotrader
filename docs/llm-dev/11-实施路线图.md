### 3.2 M1 验收

```bash
# vault 初始化
gctcli llm vault init

gctcli llm vault add --kind JEV --name "TypeSafe"

# 配对
gctcli llm providers switch --llm-rev <id> --jev-rev <id> --expected-epoch 0
gctcli llm providers pair                                          # readiness=READY pair_epoch=1

# 切换使旧决策失效（M4 才完整验证，M1 只验证 epoch 递增）
```

**M1-15 是最重要的一步**——原项目的 T039 就是这个（真实 DeepSeek + 真实 Jev 合成链路，最终 LLM `HOLD` 1413/396 tokens，Jev `hold` 1081/89 tokens）。**单元测试和 mock 不能替代它。**

原项目在这一步抓到的真实问题（必须在 M1 就解决）：

- `TOOL_ROUND_LIMIT`：模型不肯在轮次内收敛
- `CANDIDATE_SCHEMA_INVALID`：`evidenceRefs` 输出成对象数组、`uncertainty` 超枚举
- `TRUNCATED`：`max_tokens=512` 不够，调到 1024

**必须验证的失败路径**（每条都要有测试）：

- 数据过期 → `HOLD / MARKET_SNAPSHOT_STALE`，Jev 未被调用，预算未消耗（验收项 A09）
- LLM 输出不合法 JSON → `HOLD / CANDIDATE_SCHEMA_INVALID`
- LLM 引用不存在的证据 → `HOLD / CANDIDATE_EVIDENCE_UNKNOWN`
- LLM 非 HOLD 但零工具调用 → `HOLD / CANDIDATE_TOOL_EVIDENCE_MISSING`
- Jev 概率分布求和 ≠ 1 → `JEV_PROBABILITY_INVALID`
- Jev 模型漂移 → `JEV_MODEL_DRIFT`
- LLM↔Jev 方向相反 → `REVIEW / MODEL_DIRECTION_DISAGREEMENT`
- 切换配对后旧决策 → `STALE_PAIR`（验收项 A05）
- 风控信封哈希不匹配 → `RISK_ENVELOPE_MISMATCH`
- Jev 清单非 `MANIFEST_BOUND` → `JEV_FACTUAL_INPUT_NOT_RECORDED`

## 10. M8：LIVE 小额（纳入首期，Q1=E）

**前置**：M6 全部通过 + SHADOW ≥2 周安全违规率 0 + PAPER ≥2 周表现可解释 + TESTNET ≥1 周全链路无 UNKNOWN。

升级步骤：

```text
1. 配置 "acknowledgeLiveTrading": "I_UNDERSTAND"
2. 币安主网 API Key：禁提现 + 绑 IP + 只勾读取和合约
3. 主网小额充入（可承受完全损失的金额）
4. 审批一个 LIVE 策略：单笔 ≤ 最小名义额的 2-3 倍，杠杆 1，maxNewRiskIntents = 1
5. 手动触发一次决策，全程盯日志
6. 验证成交、仓位、止损单、对账
7. 逐步放大：单笔上限 ×2，观察 1 周，无异常再 ×2
8. 任何 UNKNOWN / 对账差异 / 止损失败 → 立即 FULL halt，回到 TESTNET 排查
```

**永远不要跳过 TESTNET 阶段。** 原项目的最大遗憾就是"zero `order_intents`/`exchange_orders`/`fills` in the real DB"——整条执行链只有合成验证。本方案不能重复这个错误。
