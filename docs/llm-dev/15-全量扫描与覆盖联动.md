# 15 · 全量扫描与覆盖联动（追加四原则的技术方案）

**用户追加的原则（2026-10-15，逐字保留）**：

1. LLM 通过自然语言提取筛选智能合约的策略时，应该"在远不超过币安 API 请求 QPS 上限"的前提下，把**所有的合约**都扫描一遍（不做高频策略，通常关注 1h/4h/24h/48h/72h 指标），然后给出推荐列表。
2. 被我**纳入推荐列表**的，在合约覆盖中"自动标为"启用。
3. 被我**移出追踪列表**的，在合约覆盖中"自动标为"不启用。
4. 我可在"合约覆盖" Tab 功能页中**手动打开和关闭**合约的启用按钮。**启用的合约，要优先在 LLM 通过自然语言提取筛选智能合约的策略时率先分析。**

## §1 现状评估（逐条）

- **原则 1（全量扫描）**：现筛选宇宙 = **启用集合**（`Rotator.Markets()` → `LLMToolRunner.Markets`）；T0（ticker）已是**批量全市场**（`UpdateTickers(asset)` 一次覆盖所有符号并灌缓存——rotator 每周期付一次，筛选复用缓存零权重）；T1（K 线）仅启用集合经 rotator 缓存，**未启用市场无缓存且不回源**；T2（净流入）受 `flowScanLimit`（默认前 100）。**结论：需要把宇宙扩到全量 available，并给未启用市场按需取数（QPS 预算内）。**
- **原则 2/3（推荐↔启用联动）**：写面**现成**——`SetExchangePair` RPC handler（EnablePair/DisablePair + config 持久化，`engine/rpcserver.go:1965`）；`Rotator.RefreshMarkets` 注释已预设"启用变化后应刷新覆盖"（`llm_rotation.go:214`）但**当前无调用挂钩**；LLM 侧无审计/通知/GUI 入口。**结论：需要一个 LLM 联动端点把"启用/禁用 + 刷新 + 审计 + 通知"一步做完。**
- **原则 4（手动开关 + 启用优先）**：合约覆盖页（`MarketsPage`）目前**只读**（available/enabled/in-scope 分类 + 轮询计划镜像），无开关按钮；"启用优先分析"在"宇宙=启用集合"下无意义——全量化后需要一个优先级规则。

## §2 设计

### 2.1 全量扫描（QPS 预算内）

- **宇宙**：`available`（USDT 计价永续，与 `llm/coverage/scope.go` 同规则）∪ 启用集合；来源=exchange 的 available pairs（读侧现成）。scope 的市场白名单同步扩为同一并集（证据校验不越界；仍是**有界白名单**）。
- **数据面分层与 QPS 预算**（币安 USDT-M）：

  | 层 | 覆盖 | 请求成本 | 说明 |
  |---|---|---|---|
  | T0 ticker | **全市场（588）** | **0 新增**（复用 rotator 已付的批量 ticker 缓存） | `UpdateTickers` 一次调用覆盖所有符号 |
  | T1 K 线 | 启用=rotator 缓存（0）；未启用=**按需 read-through** | 每符号 1 次 klines（limit ≤300），≤8 并发 | 复用 `fetchCandlesThroughCache`（缓存优先+回源+回灌） |
  | T2 净流入 | 启用=既有；未启用=按需 | 每符号 1 次 taker 读 | 复用现有 seam 与 worker 池 |

- **"远不超过 QPS"如何成立**：全部读经 **exchange wrapper（其 requester 自带限速器）**——不新增任何裸 HTTP 路径；并发帽 8 不变；筛选是**交互式低频动作**（非常驻），最坏 ≈500 个未启用市场 × 1-2 次读，限速器自然摊到分钟级；**扫描后 T1 结果回灌 KlineCache**——重复筛选与"日后启用"都零重复成本。
- **诚实成本上报**：`notes` 增加本次扫描的请求计数与限速状态（如"venue reads: 512 (klines 500, flow 12); rate limiter pacing active"），缺席照旧 null+计数。
- **常驻轮询不变**：rotator 仍只轮询**启用集合**（成本与新鲜度模型不变）；"全量"发生在**筛选触发时**。

### 2.2 推荐↔启用联动（原则 2/3）

- **新 LLM 端点 `LLMSetMarketTracked{market_id, tracked, actor}`**（proto 纯增量）：
  1. 解析三段式 marketId → pair；校验在 available 内（不在即拒）；
  2. 启用/禁用：**复用 `SetExchangePair` 的同源逻辑**（`exchCfg.CurrencyPairs.EnablePair/DisablePair` + config 持久化；失败回滚，fail-closed）；
  3. `Rotator.RefreshMarkets()`——覆盖/筛选/轮询立即跟随（注释预设的调用点在此兑现）；
  4. 审计 `MARKET_TRACKING_SET`（actor、subject=marketId、detail={tracked}）+ 通知事件。
- **"推荐列表"的边界**：纳入/移出是**用户的显式动作**（GUI 按钮），不是"命中即自动全启用"——`OPEN-QUESTIONS` A9 登记该口径（若你要"命中即全启用"请指出，改实现单点）。

### 2.3 合约覆盖页手动开关（原则 4 前半）

- `MarketsPage` 行尾加启停按钮（含"已启用"过滤档）→ 调 `LLMSetMarketTracked`；成功后失效缓存重取 `getexchangepairs`，覆盖分类即时更新。

### 2.4 启用优先分析（原则 4 后半）

- **扫描顺序**：先处理启用市场（其数据就位、零成本），再处理未启用（按需拉取）。
- **同级 tie-break**：主排序键并列时启用市场在前（不打断用户指定的主排序）。
- 结果 `notes` 提示该优先级。对话工具路径同逻辑。

## §3 与既有纪律的兼容

- 只读红线不变：筛选仍是只读；启用/禁用是**治理写动作**（审计+重认证？——启用/禁用是交易所配置，与审批/撤销同级敏感吗？保持与平台 `SetExchangePair` 同级（无需密码），但**必落审计**）。
- 缺席不伪装、缓存回灌、fail-closed、写审计——均沿用。
